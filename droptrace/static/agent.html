Before you leave this running

  • Keep this page in the foreground. Mobile browsers throttle or suspend background tabs, so a screen that sleeps turns into a gap in the record.
  • Nothing is stored on this device. Each measurement is posted straight to DropTrace on your network; this page keeps only a running count.
  • This measures HTTPS endpoints, not raw TCP. A browser cannot open a bare TCP connection, so a failed probe here means "this device could not complete a request", which is the question being asked: did the phone lose connectivity at the same minutes the server did?
  • Press Keep screen on after continuing. The supported way is the screen Wake Lock API, which browsers only allow over HTTPS or on localhost — on plain HTTP the page falls back to fullscreen playback, which is best effort and Android may still sleep. For an unattended run of hours, the Python agent on a laptop, or setting Android's screen timeout to its maximum, is more reliable than any page trick.
